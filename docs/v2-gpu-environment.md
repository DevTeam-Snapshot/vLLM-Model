# V2 vLLM 실행 환경 점검

점검일: 2026-09-16. 로컬 실측 완료. 사용자 확인: 배포 환경은 이미 생성된 GCP Linux VM, GPU는 NVIDIA L4, VS Code SSH로 접속할 예정입니다. 실제 VM 접속과 실측은 아직 하지 않았습니다.

## 1. 확인 결과

| 항목 | 로컬 확인 결과 |
| --- | --- |
| 기기 | MacBook Air / Apple M1 |
| OS·아키텍처 | macOS 15.7.4 / arm64 |
| CPU | 8코어 |
| GPU | Apple M1 GPU 7코어 / Metal 지원 |
| 메모리 | 8GB 통합 메모리. 전용 NVIDIA VRAM과 다름 |
| 현재 PATH | docker, nvidia-smi, vllm, uv 없음 |
| 현재 python3 환경 | vllm, torch, mlx 모듈 없음 |
| SSH 접속 설정 | ~/.ssh/config 없음 |
| 프로젝트 설정 | 외부 GPU 서버 주소 없음. 기존 Python gRPC → 이미지 API 구조 |

위 결과는 현재 실행 환경에 대한 확인이며 컴퓨터의 모든 가상환경이나 별도 설치 경로를 검색한 결과는 아닙니다. API 키·개인키·셸 히스토리는 조회하지 않았습니다.

## 2. 실행 가능성 판단

- Qwen3-8B의 16비트 가중치는 대략 16GB 규모이므로 8GB 통합 메모리에서 기본 배포안을 실행할 수 없습니다. 가중치 외에 OS, KV 캐시와 실행 메모리가 추가로 필요합니다.
- 로컬에서는 계약 검증, 가짜 추론 응답, gRPC 애플리케이션 개발을 우선 진행할 수 있습니다. 필요한 Python 의존성 설치는 별도 구현 단계입니다.
- 작은 양자화 모델을 Apple Silicon에서 실험하는 경로와 팀 배포 서버는 구분합니다. vLLM-Metal은 별도 하드웨어 플러그인 경로이며 표준 NVIDIA 배포와 기능·호환성이 같다고 가정하지 않습니다.
- 우선 권장 배포 환경은 학원에서 제공하는 Linux + NVIDIA GPU 서버입니다. 모델 크기·양자화·vLLM 버전은 실제 GPU와 드라이버 확인 후 정합니다.

공식 근거: [vLLM GPU 설치와 Apple Silicon 안내](https://docs.vllm.ai/en/stable/getting_started/installation/gpu/).

## 3. 실제 서버 점검 항목 (접속 정보 공유 없이 실행 가능)

1. 사용자가 기존 VS Code SSH 설정으로 VM에 접속합니다. 주소·사용자명·포트는 직접 원격 점검을 위임할 때만 필요하며 현재 문서 작업에는 필요하지 않습니다.
2. GPU 모델, 장수, 전체·현재 가용 VRAM, NVIDIA 드라이버.
3. Linux 배포판, Python 환경, Docker 사용 권한과 GPU 컨테이너 지원 여부.
4. 모델 저장 공간, 모델 다운로드 가능 여부, 사용 시간과 GPU 공유 정책.
5. 백엔드에서 모델 서버로 접근 가능한 내부 네트워크.

주소가 없는 상태에서 임의 호스트로 접속하거나 유료 GPU를 생성하지 않았습니다. GCP VM 생성 완료와 Linux OS는 사용자 확인을 받았습니다. 접속 정보는 설계에 필요하지 않으며 공유 없이 서버 터미널에서 진단 도구를 실행할 수 있습니다. 드라이버와 가용 메모리는 아직 미측정입니다.

## 4. 서버에서 사용할 읽기 전용 진단 도구

저장소의 `scripts/check_gpu_environment.py`를 서버에서 실행합니다.

```bash
python3 scripts/check_gpu_environment.py
```

JSON으로 OS·Python·GPU 메모리·드라이버·설치된 주요 패키지·디스크 정보를 출력합니다. 설치, 모델 다운로드, GPU 할당, 유료 API 호출은 하지 않습니다. GPU 점유 프로세스나 하드웨어 시리얼은 출력하지 않습니다.

이 도구는 GPU 실행 성능, 컨테이너 GPU 접근, 외부 통신을 검증하지 않습니다. nvcc가 없더라도 드라이버와 적절한 컨테이너가 있으면 실행 경로가 가능할 수 있으므로 설치 불가로 단정하지 않습니다.

## 5. 모델 결정 시 확인할 조건

| 상황 | 판단 방향 |
| --- | --- |
| NVIDIA VRAM 24GB급 이상 | Qwen3-8B 16비트 우선 로딩 평가. 문맥·동시성에 따라 부족할 수 있음 |
| 16GB급 | 더 작은 모델 또는 GPU·vLLM 호환 양자화 후보 검토 |
| 공유 GPU | 총 VRAM보다 실제 가용량·시간 정책 우선 확인 |
| GPU 제공 없음 | 학원에 제공 가능 여부 확인. 유료 GPU 임대는 별도 비용 결정 필요 |

대화 기록 최대 8,000토큰 외에 시스템 지시·Form·후보·출력 여유를 더한 전체 문맥을 확보해야 합니다. 처음부터 8,192 문맥으로 8,000토큰 대화 전체를 전달하지 않습니다. 모델 토크나이저와 실제 프롬프트 길이로 안전하게 절삭합니다.

- 미완료: 학원 서버 접속·실측, 최종 모델/양자화/버전 결정, 실제 vLLM 모델 로딩.
- 필요한 추가 확인: 사용자가 서버 터미널에서 실행한 진단 결과. 접속 정보 공유는 필요하지 않습니다.
- OpenAI 서비스 생성 API 사용: 없음. 제공받은 잔액 $28.94에서 이번 작업의 모델 호출 차감 없음.

## 7. 사용자 답변 반영: GCP + NVIDIA L4

- 사용자 제공: 생성 완료된 GCP Linux VM, NVIDIA L4, VS Code SSH 접속 예정.
- 공식 사양: GCP G2 계열의 L4는 GPU당 24GB 메모리입니다. GPU 장수와 실제 가용량은 VM에서 확인해야 합니다.
- 1차 채팅 후보: Qwen/Qwen3-8B, BF16, non-thinking. L4 한 장을 우선 가정하되 실제 로딩과 KV 캐시 여유를 검증합니다.
- L4 실측에서 GPU 메모리 사용률 0.85는 12,288토큰에 필요한 KV 캐시가 0.68GiB 부족했습니다. 동시 시퀀스 1개와 전체 문맥 12,288토큰을 유지하기 위해 사용률을 0.90으로 조정합니다.
- VM 시스템 RAM은 VRAM과 별개입니다. 모델 로딩 여유를 위해 시스템 RAM 32GB 이상을 권장하는 설계안이며 확정된 VM 사양은 아닙니다.
- vLLM 포트는 내부 접근으로 제한하고, FastAPI는 기존 업무용 gRPC 서비스에 연결합니다. SSH/VS Code는 개발 접속 수단이며 추론 엔진은 VM에서 실행합니다.
- GCP VM 비용은 OpenAI의 남은 $28.94와 별도입니다. 이번 작업에서 VM 생성·시작이나 GPU 임대를 수행하지 않았습니다.

공식 출처: [GCP GPU VM 사양](https://docs.cloud.google.com/compute/docs/accelerator-optimized-machines), [Qwen3-8B 모델 카드](https://huggingface.co/Qwen/Qwen3-8B).

완료를 위해 남은 실측: VM 접속 → 진단 스크립트 실행 → GPU 장수·가용 VRAM·드라이버·시스템 RAM 확인 → 실제 모델 로딩과 구조화 응답 검증. 현재 완료 상태는 **배포 하드웨어 종류 확인 및 초기 구성 설계 완료 / 원격 실측 대기**입니다.
