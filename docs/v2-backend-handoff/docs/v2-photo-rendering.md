# V2 사진 보정과 후보별 출력 비율

2026-09-29 변경. V2 `DraftImageService.GenerateDraft`에 적용합니다. V1은 기존 OpenAI 이미지 편집 경로를 유지합니다. 서버 배포 후 새로 생성하는 이미지부터 적용되며 저장된 이미지는 바뀌지 않습니다.

## 사진 처리

원본 bytes를 읽어 새 이미지에만 보정을 적용합니다. 생성형 이미지 API, 시설·풍경 교체, AI 가장자리 채우기, 촬영 시점 변경, 원근 변형은 사용하지 않습니다. 분위기·색상 선호로 실제 객실 색을 다시 칠하지 않습니다.

- 노출: 이미지 평균 밝기에 따라 배율 0.96~1.06.
- 화이트밸런스: RGB 차이가 18 이하인 중간 밝기 픽셀이 표본의 5% 이상일 때만 채널별 배율 0.98~1.02. 강한 색조는 자동으로 없애지 않습니다.
- 대비·채도: 각각 1.02배.
- 수평: 384px 이하 표본에서 서로 떨어진 긴 가로선 3개 이상의 정렬을 검사합니다. ±2도 범위를 0.25도 단위로 검색하되 경계값·0.5도 미만·불명확한 최적값은 건너뜁니다. 기하 보정은 추정이므로 실제 사진 검수가 필요합니다.
- 회전으로 생기는 빈 모서리는 안쪽으로 잘라내며 원본 가로세로 비율로 맞춥니다. 초기 안쪽 자르기가 10%를 초과하면 회전하지 않습니다. 비율을 다시 맞출 때 추가로 일부 잘릴 수 있습니다. 따라서 원본 비율 유지는 사진 전체의 픽셀 보존을 의미하지 않습니다.

세 후보와 재생성은 동일한 사진 보정을 사용합니다. 원본 파일 보관은 기존과 같이 Backend 책임입니다.

## 세 후보

기존처럼 direction별로 독립 RPC를 한 번씩 호출합니다. 요청·응답 필드 번호, enum 이름, PNG MIME, 회차와 식별자 규칙은 그대로입니다. direction은 기존 광고 방향 식별자이면서 다음 고정 출력 정책에 대응합니다.

| direction | 표시할 이름 | 출력 |
| --- | --- | --- |
| 1 / ROOM | 원본 비율 | 긴 변 1024, 짧은 변은 비율에 따라 반올림. 예: 1200×800 → 1024×683 |
| 2 / EMOTION | 정사각형 광고 | 1024×1024, 비율 유지 확대/축소. live는 OpenAI가 자르기 중심 추천 |
| 3 / BENEFIT | 자동 추천 | live는 OpenAI가 사진을 보고 원본 비율 또는 정사각형 선택 |

live에서는 보정된 사진의 최대 1024px JPEG 미리보기와 확정 문구를 OpenAI Responses API에 전달합니다. 구조화 응답으로 자르기 중심, 네 모서리 중 문구 위치, 그라데이션 농도, 추천 비율을 받습니다. 1·2번의 비율은 코드에서 고정하며 3번에만 추천 비율을 적용합니다. 원본이 정사각형이면 세 후보 모두 같은 비율일 수 있습니다. Vision의 위치 판단은 추정이며 시설·창문이나 중요 피사체 보존을 보장하지 않으므로 결과를 검수하세요.

모든 후보는 사진이 캔버스를 채우고 문구가 안쪽에 겹칩니다. 단색 바깥 패널은 없습니다. 문구 뒤에만 사진이 비치는 어두운 그라데이션을 사용합니다. 2회차에는 다른 적절한 배치를 추천하도록 요청하지만 서로 다른 결과를 보장하지 않습니다. 확정된 숙소명과 문구는 바꾸지 않습니다. 극단적으로 좁은 이미지 등에서 최소 글자 크기로도 전체 문구를 배치할 수 없으면 기존 `COMPOSITION_FAILED`를 반환하며 문구를 잘라내지 않습니다.

fake만 외부 호출 없이 중앙 자르기·고정 배치를 사용하고 3번은 남는 면적이 85% 이상일 때 정사각형을 선택합니다. live는 후보당 OpenAI를 한 번 호출하므로 세 후보는 총 세 번 호출합니다. 자동 재시도와 fake 대체는 없습니다. 키 누락, 인증 오류, 제한, 타임아웃, 잘못된 구조화 응답은 오류로 반환합니다. 사진을 생성형 모델로 다시 그리거나 주변을 생성해 채우지 않습니다.

## Backend·React 연동

- 세 번의 호출과 사용자의 최종 후보 선택 흐름은 유지합니다. 호출 순서 대신 `direction`으로 후보를 구분하세요.
- `1024×1024` 고정 검증을 제거하고 반환 PNG의 실제 width/height를 읽어 저장합니다. 응답에 새 필드는 없습니다.
- React 미리보기는 이미지의 실제 비율을 유지해야 합니다. 이미지 자체에는 `width: 100%; height: auto`를 사용하거나 고정 카드 안에서 `object-fit: contain`을 적용합니다. 여기서 카드의 여유 공간은 다운로드 이미지에 포함되지 않습니다.
- 결과 PNG에 `object-fit: cover`를 강제하면 원본 비율 후보까지 잘려 보입니다. 다운로드 시에도 정사각형으로 재가공하지 마세요.
- 3번은 “자동 추천”으로 표시합니다. 실제 선택된 비율은 PNG 크기로 확인할 수 있습니다. 원본이 정사각형이면 두 출력 방식의 차이는 없습니다.
- 기존 결과 캐시와 새 결과를 구분해 배포 시 렌더러 버전을 올리거나 기존 초안 캐시를 무효화하세요. 이 서버는 캐시·DB를 소유하지 않습니다.
- 원본 사진은 별도 보존합니다. 이번 변경은 사용자가 직접 보정값·자르기 위치를 편집하는 UI/API를 추가하지 않습니다.

V2 live 이미지에는 `OPENAI_API_KEY`가 필요합니다. 기본 분석 모델은 `OPENAI_VISION_MODEL=gpt-4.1-mini`, 제한 시간은 `OPENAI_VISION_TIMEOUT_SECONDS=60`입니다. `OPENAI_BASE_URL` 기본값은 `https://api.openai.com/v1`입니다. HealthCheck는 한글 폰트·키·모델 이름 설정만 확인하며 실제 인증을 확인하지 않습니다. 채팅은 기존 Qwen/vLLM을 유지합니다. `IMAGE_MODEL`, `IMAGE_TIMEOUT_SECONDS`는 V1 설정입니다. [실제 API 테스트 및 배포 명령](v2-live-deployment.md)을 참조하세요.

## 검증

`uv run --python .venv-v2/Scripts/python.exe --no-project python scripts/check_local.py`로 전체 회귀 테스트를 실행합니다. `scripts/smoke_local.py`는 실제 서버 프로세스를 띄워 원본 비율·정사각형·자동 추천의 두 회차를 확인하고 `artifacts/local-smoke`에 저장합니다. Linux에서는 Python 경로를 `.venv-v2/bin/python`으로 바꿉니다.
